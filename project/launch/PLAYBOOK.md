# Launch playbook

Drafts for each channel are in this folder. Post them yourself, from your own
accounts, one channel at a time. Nothing here is automated.

## Before you post

- [ ] A complete release is out (all channels published, verify job green).
- [ ] `brew install dumhouse/tap/clavis`, the Scoop install and `docker run
      dumhouse/clavis` all work on clean machines.
- [ ] The landing page and README load fast and the quick start works as written.
- [ ] GitHub Discussions is on, and you can answer issues for the first week.
- [ ] Someone other than you has followed the quick start once.

## Order

| Day | Channel | Draft | Notes |
| --- | --- | --- | --- |
| Tue–Thu, 8–10am US Eastern | Show HN | `show-hn.md` | Title, link to the repo, a first comment with context. Stay online for hours. |
| Same day or next | Product Hunt | `product-hunt.md` | Schedule it; needs a maker account and a gallery. |
| Day after | r/selfhosted | `reddit.md` | Read the subreddit's self-promotion rules first. |
| Later that week | r/devops, r/golang | `reddit.md` | Rewrite the intro for each audience; do not cross-post. |
| Within a week | dev.to | `devto.md` | A technical write-up, not an announcement. |
| Any time | X / Bluesky | `social.md` | Short posts with the hero screenshot. |

## How to post well

1. Lead with the problem, then what it does, then what it does not do.
2. One honest limitation beats five features. The agent threat model is yours.
3. Link the repo and docs, not the signup page; there is no signup.
4. Answer every comment in the first hours, including the harsh ones.
5. Do not ask friends to upvote. HN and Reddit detect it and penalize it.

## Listings (after launch)

awesome-selfhosted and the CNCF landscape both expect a stable demo and some
evidence of use. Wait until there are real users, then submit the prepared
entries in `listings.md`.
